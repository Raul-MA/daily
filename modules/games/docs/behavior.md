# Games data and session lifecycle

## Problem

The shared-device score tracker retains its original ledger interface and portable game history while using Daily's document, routes, activity registry and worker. Source: `game-tracker`, commit `80fe90af080bbe1d3b17778369af011d9b90e897`; mappings are in `reports/games-source-map.json`. Original code/installations remain unchanged.

## How It Works

- `src/backend/` retains player/game CRUD, archival rules, session scoring, outcomes, history, statistics and full JSON export. Validators live under `backend/core/validation/`; statistics accumulation is split into small functions without changing its derived results.
- Payload: `daily:v1.modules.games = { version: 1, data }`. The inner schema retains `appId/appSlug: board-game-score-tracker`, `schemaVersion: "1.0"`, settings, players, games, sessions and metadata. Original future-major rejection and additive same-major import normalization remain. Navigation never initializes records.
- `src/service.js` binds the original storage API to the root. Reads return fresh data plus an internal symbol revision that spreads through feature operations and is excluded from JSON. Stale domain saves reject before writing. Unsupported module versions propagate; the legacy standalone corruption fallback is never used by the mounted app.
- Explicit settings language changes update the global preference and module in one commit. Reads/exports use the shared preference; imports retain it. Authored EN/ES copy uses `backend/core/translations/` and explicit `frontend/app/copy.js` calls. Original English scoring labels/domain values stay unchanged; only their display is translated. User names, notes and snapshots are passed verbatim through the retained escaping boundaries.
- `src/activity-sync.js` saves session and activity changes together. The shared activity uses the session ID/reference and name snapshot; its running clock derives from the original `startedAt`. Scores and rendering never restart it. Completion records the derived or overridden duration; reopening retains the original start and explicit timing corrections. Other app activities remain intact. A quota failure cannot leave a timer without its session or vice versa.
- `src/view.js` mounts the split original screens. Transient selections, editing IDs, history filters and notifications survive native route/language renders in the shell's Games UI context. No legacy worker/manifest is registered. Theme/CSS is scoped; toasts keep the shared header usable and fixed mobile navigation includes the safe area.
- Routes: `/games` and `/games/new` open setup; `/games/session` opens the current-session screen; `/games/session/:id` refers to that particular session; `/games/history` and `/games/history/:id` open history/details; `/games/catalog`, `/games/players`, `/games/stats`, `/games/settings` open management/settings. A stale session ID cannot open a different active session; completed references show their historical detail or a missing-record view.
- Setup, scoring modes/outcomes, rounds, ranking, timing, history/filter/winner summaries, catalog/player management, statistics, confirmation dialogs, settings and backup diagnostics use the shared language. Date formatting uses the selected locale; numbers, IDs and timer timestamps remain unchanged. `copy.js` reads the region language already set at render start, avoiding repeated storage reads for each label.
- Success/error notifications keep their source message and original expiry. Rendering translates it in the current language; backup reminders regenerate their localized date/age. Thrown write errors retain a persistent notice through a language remount, alongside the unsaved draft.
- `frontend/app/drafts.js` gives source forms stable IDs and wraps setup/session controls for draft tracking. Language changes and notification expiry retain inputs. Revision stamps retain stale player/game/session drafts instead of overwriting another tab. Successful actions clear saved drafts; failed storage writes remain visible without discarding them.
- Backup filenames and full original JSON format remain. Import is **replace-only**. Preview validates identities, versions, IDs, participants, rounds, scores, results and winner references before any write. Confirmation requires a recovery download, rejects stale previews and atomically replaces Games plus its activity state. Cancellation leaves all records intact. The previous root remains in `daily:v1:recovery`.

## Gotchas

- There is only one active session. The guard exists both when starting and in validation. New setup offers the existing session instead of silently replacing it.
- Competitive sessions require at least two participants; cooperative sessions permit one. Archived players are excluded from new setup while their IDs/snapshots remain in history. Referenced players/games are archived; unused records can be deleted.
- `highest_score_after_rounds` uses its snapshotted higher/lower direction. `first_to_points` always favors the higher total, including old sessions with a false direction field. Shared best scores retain all tied winners.
- Arithmetic score inputs support `+ - * /`, show a preview, truncate valid fractional results and save whole integers; negatives remain valid. There is no `eval`. Internally `updateScore(data, selection, value)` replaces the original five-argument signature to meet the parameter limit. The characterization adapter changes only that boundary.
- Competitive result sessions require an outcome for every participant. Cooperative sessions require one shared Win/Loss, with empty rounds/results/individual winners. Cooperative records remain separate from competitive W-L-T and head-to-head statistics.
- Completing a session saves winner IDs. Reopening preserves the session's configuration, participants, timestamps and duration override for correction, clearing winners until completion. Duration override wins over completed-minus-start math; statistics are derived from completed history and keep per-game averages separate.
- Original browser workflows retain all 136 assertion sites. Fixture wrappers/readback, native URL selectors, scoped theme and explicit preview/recovery confirmation adapt storage/router/import boundaries. The [migration inventory](../../../reports/migration-test-inventory.md) maps characterization, shared activity/storage, localization and browser contracts.
- Real iPhone/process-restart, physical migration and release acceptance remain pending. Browser offline and controlled-clock results are local evidence only.
